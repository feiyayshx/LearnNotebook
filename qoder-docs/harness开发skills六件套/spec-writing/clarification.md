# 澄清工具库（模糊词清单 + 分维度问题库 + 提问话术）

阶段 2（需求澄清）与阶段 4（质量门禁）使用本文件。

## 一、模糊词 / 风险词清单

命中以下词汇即必须澄清或改写为可度量表述：

**中文**：等、等等、之类、相关、尽量、尽可能、较快、合理、合适、友好、方便、灵活、强大、稳定、高效、一些、多种、若干、偶尔、一般、通常、大概、差不多、支持多种格式、用户友好、响应迅速、操作简单

**英文**：etc.、and so on、appropriate、fast、quick、reasonable、user-friendly、flexible、robust、efficient、several、various、some、usually、generally、approximately、as soon as possible

**改写原则**：主观词 → 可度量指标。

| 模糊表述 | 改写为 |
|----------|--------|
| 响应较快 | P95 响应时间 ≤ 500ms |
| 支持导入 Excel 等格式 | 支持 .xlsx 与 .csv，单文件 ≤ 10MB |
| 大量数据 | 单表 100 万行，列表分页每页 20 条 |
| 用户友好提示 | 报错时展示具体原因与操作建议的 toast，3s 自动消失 |

## 二、分维度澄清问题库

按维度逐项自查，无答案的点即为待提问项：

### 角色与权限
- 使用者角色是否穷举？各角色可见内容、可执行操作有何差异？
- 未登录 / 无权限 / 权限变更中途，系统行为分别是什么？

### 主流程
- 起点：用户从哪里进入？终点：什么状态算"完成"？
- 每一步的触发者与系统响应？允许回退吗？中断后如何恢复？

### 异常与边界
- 必填为空 / 格式非法 / 超长输入？
- 网络失败 / 超时 / 重复提交（双击、刷新重提）？
- 数量为 0、达到上限、超出限制？
- 并发操作同一数据？数据已被他人修改/删除？
- 数据不存在 / 已过期 / 已作废？

### 数据约束
- 每个字段：类型、必填、默认值、取值范围、精度（金额必须明确单位、小数位、舍入方式）
- 数据来源：用户输入 / 接口下发 / 系统生成 / 导入？
- 存量历史数据如何处理？需要迁移或兼容吗？

### 交互与状态
- 页面四态：加载中 / 空数据 / 错误 / 成功，各长什么样？
- 核心对象状态机：有哪些状态？什么事件触发流转？谁是终态？允许逆向流转吗？

### 非功能需求
- 性能：并发量级？响应时间上限？数据量级？
- 兼容：浏览器 / 机型 / 小程序基础库版本范围？
- 安全：敏感字段清单？脱敏规则？需要操作审计日志吗？

### 集成与依赖
- 依赖哪些既有模块 / 接口 / 第三方服务？对方不可用时降级策略？
- 是否改动既有接口契约？旧调用方如何兼容？

## 三、冲突处理话术

**输入源之间矛盾**：
> 【冲突确认】原型第 X 页显示的是 A，您口述的是 B（代码现状是 C）。三者不一致，以哪个为准？

**代码现状与新需求矛盾**：
> 【现状冲突】现有代码行为是 X（位置：{文件}），新需求要求 Y。方案一：改造存量逻辑（需评估兼容性与回归范围）；方案二：新增旁路实现，存量不变。选哪个？

**需求之间矛盾**：
> 【逻辑冲突】FR-003 要求"提交后不可修改"，FR-007 要求"提交后可编辑金额"。请确认两者的适用边界。

## 四、假设确认话术

> 【假设确认】关于 {X}，输入材料中未明确。我的假设是 {Y}，理由是 {Z}。请确认，或告知正确处理方式。

**要点**：每条假设单独提出，给出自己的推荐答案和理由，让用户只需做选择题而非填空题。
