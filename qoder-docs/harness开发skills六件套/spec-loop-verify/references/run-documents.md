# 运行文档集规范（防漂移）

> 四份文档构成循环的"锚"：**plan.md 是唯一驱动，report/fixes/adr 是过程账本**。任何一步完成后必须先回写文档再做下一步；文档未更新 = 该步未完成。

## 更新时机矩阵（强制）

| 事件 | 更新文档 | 时机 |
|------|----------|------|
| 交付标准对齐完成 | adr.md（ADR-001）、plan.md 头部 | 立即 |
| 检查计划生成 | plan.md | Phase 1，用户确认后冻结 |
| 预检完成/失败 | preflight.md | Phase 2 |
| 凭据核销（缺失项一次性向用户索取） | preflight.md + plan.md（对应 CP 预标 BLOCKED） | Phase 2，进循环前 |
| **每个检查点执行完** | plan.md 状态列 + evidence/<CP-ID>/ | **立即，再执行下一个** |
| **每个修复动作**（含构建/重启） | fixes.md 追加一条 | **立即** |
| 计划/范围/预期值变更 | adr.md 一条 + plan.md 同步改 | 变更前（先 ADR 后改） |
| 每轮结束 | report.md 刷新 + adr.md 轮次小结 | 进入下一轮前 |
| 收尾 | report.md 定稿 + 清理状态 | Phase 4 |

## plan.md — 检查计划（唯一驱动）

```markdown
# 检查计划：<模块名>
- 依据：① <文档路径@版本> ② <原型路径>（冲突裁决顺序：...，见 ADR-001）
- 范围：<含/不含>；修复白名单：<路径列表>
- 环境：PROFILE=<>；MAX_ROUNDS=<>；修复模式=<受限自动/只报告/先确认>
- 状态图例：⬜未测 ✅PASS ❌FAIL ⛔BLOCKED 🚨ESCALATED

## 检查点
| CP-ID | 层级 | 端 | 出处 | 状态 | fail_count | 轮次 | 证据 |
|-------|------|----|------|------|-----------|------|------|
| CP-001 | FUNC | backend | 文档§x.y | ⬜ | 0 | - | - |

### CP-001 <标题>
- 前置：<账号/数据/状态>
- 步骤：<可机械执行的动作序列>
- 预期-接口：<状态码/响应字段/枚举值>
- 预期-DB：<表、行数、关键列值>
- 预期-UI：<组件、文案、禁用/加载态、动效>
- 造数：<需要的测试数据>（无则略）

## 造数与账号需求汇总
## 凭据需求矩阵（Phase 2 一次性核销）
| CP-ID | 所需账号/凭据/角色 | 用途 | 核销（✓/✗） |
## 数据依赖链与共享造数
| 造数 ID | 内容（状态/数据） | 服务 CP 列表 | 造数 SQL | 清理 SQL |
## SPEC-ISSUE（标准文档冲突与采用假设）
| # | 冲突点 | 两处原文 | 采用假设 | 状态 |
```

规则：
- CP-ID 用 `CP-<序号>` 稳定编号；另设"出处"列映射回标准文档条目号（如 AC-01、BR-03、E2E-02、原型分区），禁止用条目号当 CP-ID（不同文档编号体系不同，避免耦合）。
- 循环中每轮开始必须重读本文件；只允许改 状态/fail_count/轮次/证据 四列，其余改动须 ADR。

## report.md — 验证报告（每轮刷新）

```markdown
# 验证报告：<模块名>（最近更新：第 <n> 轮）
- 结论：<X/Y PASS，Z BLOCKED，W ESCALATED>（未全 PASS 禁止写"通过"）
- 环境：<网关/DB/服务版本 commit>；依据：见 plan.md

## 轮次概览
| 轮次 | PASS | FAIL | BLOCKED | 修复数 | 备注 |
## 追溯矩阵
| 出处条目 | CP-ID | 层级 | 结果 | 轮次 | 证据路径 |
## 不符项与修复摘要（链接 fixes.md 条目）
## SPEC-ISSUE 与假设
## 残余风险与待决项（BLOCKED/ESCALATED/待用户裁决）
## 非目标回归证据（diff 范围、主流程抽测、依赖红线）
## 造数清理状态
```

## fixes.md — 修复记录（每个修复动作一条）

```markdown
## FIX-<nn>｜CP-xxx｜第 <n> 轮｜<时间>
- 现象：预期 <>，实际 <>（证据：evidence/<CP-ID>/）
- 根因：<一句话根因 + 定位依据（日志/断点/代码行）>
- 同类排查：<同模式扫描命中点列表；整类修复/逐点修复（ADR-<nnn>）；白名单外命中仅报告>
- 参照实现：<参考的既有实现（文件/组件），风格一致性依据；无参照需说明理由>
- 修复：<文件:改动摘要>（白名单内 ✓）
- 构建/生效：<按项目构建命令重建并重启服务 / 前端热更新>
- 单点重验：<PASS/FAIL + 新证据路径>
- 全量回归：<第 n+1 轮结果>
- 状态：<已闭环 / 升级 ESCALATED（第 3 次失败）>
```

## adr.md — ADR 决策日志（ADR-lite）

```markdown
## ADR-<nnn>｜<类型>｜<时间>｜状态：已生效/待确认/已废弃
- 背景：<触发此决策的情况/问题>
- 决策：<做了什么决定>
- 理由：<为什么>
- 影响：<对计划/范围/预期/环境的影响>
```

**必须写 ADR 的场景：**

| 类型 | 场景 |
|------|------|
| 基线确认 | Phase 0 对齐结果（ADR-001，恒定第一条） |
| 预期裁决 | 标准文档冲突取值、模糊条款的解释（关联 SPEC-ISSUE） |
| 范围变更 | 检查点增删改、白名单调整、Non-Goal 调整 |
| 修复决策 | 多种修复方案的取舍；同类缺陷整类修复策略；触及递归依赖模块的授权 |
| 环境决策 | 目标环境切换、造数授权、账号方案选择 |
| 升级 | ESCALATED 的根因与建议；MAX_ROUNDS 用尽后的处置 |

原则：ADR 只追加不修改；废弃的决策不删除，追加状态"已废弃"并注明被哪条 ADR 取代。
