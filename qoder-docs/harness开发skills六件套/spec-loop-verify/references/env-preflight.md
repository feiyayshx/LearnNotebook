# 环境预检手册（Phase 2）

> 本手册**项目无关**：所有地址、凭据、服务清单、端口均在预检时从**当前仓库活配置探测 + 向用户询问/核对 + 方案选择**获得；沿用任何历史项目取值即违规。
> 原则一：连接信息**不猜、不硬编码**——从构建/配置文件定位配置来源，从配置来源读中间件连接；业务服务按用户确认的方式启动。
> 原则二：**活配置为准**——文档（含 AGENTS.md、README 端口表）可能过时，一律以构建文件/配置中心/运行中服务的实际配置为准；通路必须发真实请求验证，不看配置"存在"即判通。
> 预检范围由 **plan.md** 决定（涉及哪些服务/表/账号/任务就检哪些）。任一硬项失败 → 停止并输出缺口清单。

## 0. 环境画像核对（预检第一步）

基于 Phase 0 的环境画像，逐项探测并向用户**核对**（探测结果 + 选项，不做开放式提问）。项目若有 env-bootstrap 产物（AGENTS.md、`docs/maps/` 五张地图——尤其环境地图与接口地图、`service-map.yaml`、`docs/env/env-report.md`），先读作探测线索——但**活配置仍为准**（原则二），文档结论不能替代真实连通验证。预检与循环中遇到远程环境类故障（502/超时/连接失败），按项目 `.qoder/rules/` 的「远程环境排障顺序」执行（先环境后代码八步序列，env-bootstrap D1-7 生成；项目无此规则时按 连通性→容器→网关→注册→配置→DB→日志→代码 的顺序自查），禁止开局就改代码：

1. **构建体系**：仓库根/子目录探测 `pom.xml`（Maven）/ `build.gradle`（Gradle）/ `package.json`（Node）/ `go.mod` 等，确认后端与前端各自的构建、启动、重建命令；
2. **配置来源方案选择**（三选一或组合，记入 preflight.md）：
   - **A 配置中心**（Nacos/Apollo/Consul/Spring Cloud Config 等）：从构建文件或 bootstrap 配置中提取地址；地址与凭据向用户核对/索取，禁止假设默认口令可用；
   - **B 本地配置文件**（application*.yml/.properties/.env 等）：确认生效的 profile 与文件优先级；
   - **C 环境变量 / 容器编排**（K8s ConfigMap、docker-compose）：请用户提供导出方式或只读访问途径；
3. **中间件清单**：从配置提取本次 plan 涉及的 DB / 缓存 / MQ / RPC 注册中心 / 任务调度平台；配置里没有而 plan 需要的 → 向用户索取。
4. **交付形态 → 预检章节适用矩阵**（按 Phase 0 确认的形态勾选，不适用章节在 preflight.md 记 N/A 及理由）：

| 交付形态 | 适用章节 |
|----------|----------|
| 纯后端 API（微服务/单体） | §1-4、§7、§8（有网关才检 §4；单体只有一个进程） |
| Web 管理端 / H5 / 纯静态站 | §1、§4-5、§7（纯静态站免 §1-4，仅 §5 + 部署产物核对） |
| 小程序 | §1、§4、§6、§7 |
| 原生 App / 桌面端 | §1、§4、§6A、§7 |
| CLI 工具 / SDK·库 | §1（如依赖外部服务）、§2（如有 DB）、§3A、§7 |
| 数据管道 / 批处理 | §1-3、§7、§8 |

## 1. 解析连接信息

1. 按 §0 选定的配置来源方案，读取 plan.md 涉及服务的生效配置（含 profile 分段），确认命名空间/分组/文件命名规则；
2. 配置中心方案用其 Open API 或 CLI 拉取配置（凭据向用户索取；仅当用户确认为本地开发默认口令时才可试用默认值）；
3. 提取并记录（**写入 preflight.md 时密码脱敏**）：各数据源（业务库 + 系统/公共库）、缓存、MQ、RPC registry、任务调度 admin（如 plan 涉及 Job/MQ 检查点）。

## 2. 数据库断言通道

按优先级建立 SQL 执行通道（验证全程复用；哪一级可用记入 preflight.md）：

1. **本机数据库 CLI**（如 `mysql`/`psql`）：`<cli> -h<host> -u<user> -p<pass> <db> -e "<sql>"`；
2. **一次性脚本**：在 `RUN_DIR/scripts/` 用对应驱动（如 Node `mysql2`/`pg`）写一次性查询脚本（临时安装，**不改动任何仓库 package.json**）；
3. **docker exec**：仅当配置指向容器数据库时 `docker exec <db-container> <cli> ...`；
4. 以上均不可行 → 向用户询问可用通道（跳板机/Web 控制台/用户代查），并按所选方案确定证据留存方式。

**交付不涉及可直连数据库**（SaaS 后端、serverless、纯前端、SDK 等）→ 本节记 N/A，DB 断言由**替代通道**承担并记入 preflight.md：查询类 API 回读断言、可观测产物（导出文件/日志/事件）断言、或用户提供的只读控制台；plan.md 中"预期-DB"列相应改为"预期-数据（通道：<替代方式>）"。

自检：`SELECT 1` 成功；对 plan.md 登记的每张表逐一核对存在（如 `SHOW TABLES LIKE '<table>'`）；缺失即硬项失败（增量 SQL 可能未执行）。替代通道场景则对 plan 登记的每类数据对象做一次真实回读自检。

## 3. 本地业务服务

仅启动 plan.md 链路涉及的服务。**服务清单表在预检时现场生成**（从仓库模块结构 + 网关路由/注册中心提取，向用户核对），格式：

| 服务 | 端口 | 启动命令 | 健康检查 |
|------|------|----------|----------|
| （探测+核对后填写） | | | 如 `/actuator/health`、`/v3/api-docs`、登录接口可拿 token |

- 启动方式向用户确认：本地命令启动 / IDE 启动 / docker-compose / 已有共享测试环境（则跳过本节，仅做连通性验证）；单体应用只启动一个进程，本节表格退化为一行；
- 后台启动并轮询日志，出现框架就绪标志（如 `Started *Application`）且无启动失败标志才算就绪；
- 修复后重建：按 §0 确认的重建命令执行（改过被依赖的公共/API 模块先构建安装该模块）并重启该服务。

**§3A CLI 工具 / SDK·库（替代本节）**：CLI 确认构建产物可执行（`--help`/`--version` 真实调用）；SDK·库在 `RUN_DIR/scripts/` 建独立示例工程，按 README/文档安装本地构建产物并完成一次最小消费调用（import + 核心 API），失败即硬项失败（文档与产物不符）。

## 4. 网关/代理通路（仅存在网关/反向代理时；单体直连则仅核对服务端口与前端代理）

- 从交付标准文档提取本模块 API 前缀（如 `/xxx/v1/...`），**逐一确认通路存在**：
  - 查网关路由配置（本地文件与配置中心两处）是否有对应路由；
  - 查前端工程的 API base 配置与 dev 代理（如 `.env*` 的 base 变量与 `vite.config.*`/`webpack` proxy），确认请求实际落点；
  - 前缀在仓库与配置中心都不存在 → 调用必然 404：记 `BLOCKED` 上报（网关等全局基建是否允许改动，以 Phase 0 红线为准；未获授权禁止自行新增）。
- 通路自测：**每个前缀至少一次真实带认证的请求**（如 plan 中任意列表接口），返回项目统一响应结构（Phase 0 确认的包装格式）即通；超时/502/404 均为硬项失败。

## 5. Web 前端（管理端/H5）

- 包管理器探测（lock 文件：pnpm-lock/yarn.lock/package-lock）→ `install`（首次）→ dev 启动，端口以实际输出为准；
- 浏览器通道：优先 **chrome-devtools MCP**（list_pages / new_page / navigate_page / take_snapshot / click / fill / take_screenshot / evaluate_script / list_network_requests / list_console_messages）；失败降级 **playwright / browser-use**（脚本写在 `RUN_DIR/scripts/`，不污染仓库）；
- 账号（运行时向用户索取）：具备 plan 涉及菜单权限的账号 + 一个无权限对照账号。

## 6. 小程序 —— 微信开发者工具自动化（仅交付含小程序时）

1. 构建：按项目命令编译小程序产物（如 uni-app 的 `dev:mp-weixin`，产物目录以构建输出为准；保持 watch 运行）；原生小程序工程则直接以项目根为准。
2. 微信开发者工具：
   - 确认已安装并向用户核对 CLI 路径（macOS 默认 `/Applications/wechatwebdevtools.app/Contents/MacOS/cli`；Windows 默认 `C:\Program Files (x86)\Tencent\微信web开发者工具\cli.bat`；不存在则向用户确认安装路径）；
   - **设置 → 通用设置/安全设置 → 开启"服务端口"**；用 cli 打开项目：`cli --project <产物目录>`；
   - 关闭"校验合法域名"（详情 → 本地设置）。
3. 自动化驱动（按项目已有依赖选择，二选一）：
   - 项目已有 `@dcloudio/uni-automator`（devDependency）：按其 jest preset 或直接引用其 API；
   - 或 `miniprogram-automator`（微信官方）：`automator.launch({ cliPath, projectPath, port })`。若缺包，在 `RUN_DIR/scripts/` 临时安装，不改仓库依赖。
3.1 **预检时实测自动化能力分级**（不等循环中才发现）：依次实测 ① 元素查询+点击 ② 页面 data/路由读取 ③ screenshot，可用级别记入 preflight.md。已知坑：Windows 上 Node≥18 无法无 shell spawn .bat（launch 失败 → 改外部 `cli auto --auto-port` + `automator.connect`）；新版工具 checkVersion 报 `reading 'split'`（monkey-patch 包容）；残留 `.ide` 文件致端口一次性（清理后重开工具）。
3.2 **能力不足的结论约束**：若仅 ②/③ 可用，涉及元素级 UI 断言的 CP 预标「结论上限 BLOCKED」并提前告知用户（可选 H5 同源页用浏览器工具替代走查，或用户人工配合）；禁止循环中静默降级后仍判 PASS（SKILL 铁律 3）。
4. 登录态：需鉴权的接口须有效 token。方案选择（**记入 ADR**）：① 开发者工具内已登录账号（走真实登录）；② 向用户索取测试 token，经 `miniProgram.evaluate` 写入 storage 后 reLaunch；③ 用户在工具里手动登录一次后接管会话。
5. appid：从项目环境配置文件读取，禁止硬编码。

## 6A. 原生 App / 桌面端（仅交付含对应形态时）

1. **自动化通道方案选择**（预检时实测，记入 preflight.md 并记 ADR）：
   - 原生 App：项目已有 UI 测试工程（XCUITest/Espresso/uni-automator 等）→ 优先复用；否则 **Appium**（真机/模拟器，向用户确认设备与系统版本）或 **Maestro** 等脚本化工具；均不可行 → 若存在 H5/Web 同源实现，用浏览器工具替代走查（记 ADR，结论上限按降级规则）；
   - 桌面端：项目已有自动化测试工程 → 复用；否则 OS 级 UI 自动化（如 macOS AXUI/Windows UIA 类工具）；均不可行 → 用户人工配合方案。
2. **能力分级实测**（同 §6 3.1 规则）：依次实测 ① 元素查询+交互 ② 应用状态/路由读取 ③ 截图；级别记入 preflight.md；仅 ②/③ 可用时，元素级 UI 断言的 CP 预标「结论上限 BLOCKED」并提前告知用户。
3. 测试账号/登录态、测试设备、签名/证书等运行必需项 → 列入凭据需求矩阵，§7 一次性核销。

## 7. 凭据核销与造数（plan 驱动）

**凭据核销（进循环前必须完成）：**

1. 读 plan.md「凭据需求矩阵」，逐项核销：管理端有权限账号、无权限对照账号、小程序各状态测试用户（按 plan 的角色/状态要求）、配置中心凭据、任务调度 admin、小程序开发者工具登录态、网关认证所需的 token 与客户端标识；
2. 缺失项**一次性汇总**向用户索取，禁止发现一个问一个；
3. 核销失败的凭据 → 对应 CP 在 plan.md 预标 BLOCKED，并记入 preflight.md；禁止带未核销凭据进循环。

**造数（按 plan.md「数据依赖链」）：**

- **造数授权**：共享测试库必须用户明确同意（记入 ADR）；
- 按依赖链准备共享造数（造一次服务多个 CP），执行顺序与 plan 一致；
- 业务名/备注统一前缀 `[VERIFY]`，手机号用预留段（如 `1990000xxxx`），便于识别与清理；
- 造数 SQL 与清理 SQL 成对保存在 `RUN_DIR/scripts/`；报告附"已清理/待清理"状态；
- 时间敏感场景（如到期/窗口期）造数用后必须还原或删除；
- 禁止修改存量真实数据；金额字段一律 `DECIMAL`，与表精度一致。

## 8. 任务调度 / MQ（仅 plan 涉及时）

- 任务调度（如 XXL-Job/Quartz 管理台）：从配置取 admin 地址与执行器名；触发 plan 指定的 Job（admin 手动触发或本地等价调用），断言后**至少再触发一次验证幂等**。
- MQ（如 RabbitMQ/Kafka/RocketMQ）：需要断言消息生产/消费时，从配置取连接，经管理台或 API 核对队列/消息。

## 预检输出

`RUN_DIR/preflight.md`：环境画像与方案选择结果、各项 通过/失败、连接摘要（脱敏）、DB 通道级别、小程序自动化能力级别与登录方案、造数授权、阻塞项与待用户处理清单。
