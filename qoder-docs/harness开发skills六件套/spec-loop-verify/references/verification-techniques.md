# 验证技术手册（Phase 3）

> 每个检查点固定节奏：**操作 → 断言接口 → 断言 DB → 断言 UI**。三层断言全部符合预期才 PASS；任何一层不符即 FAIL，差异全部记录（不只记第一个）。所有预期值只取自交付标准文档（见 plan.md 出处列）。

## 通用断言规则

- **金额/数值**：`BigDecimal` 精度比对，禁止浮点近似；涉及计算公式时，从交付标准提取公式原文，按公式逐步重算（如 单价×数量×系数），不得自创算法。
- **枚举/状态**：数值与文案双比对（DB 存数值 ↔ 字典/文档文案 ↔ UI 展示三者一致）。
- **文案**：与交付标准/原型用词一致；标准中明令禁止的措辞（如有）列入反向断言。
- **时间/周期**：按标准中的规则断言（起止关系、顺延、窗口期），含边界日（当天、±1 天）。
- **防重/幂等**：同一操作连续提交两次，第二次必须被拦截（防重拦截注解/唯一约束/状态机，具体机制以项目为准），且库中无脏数据；Job/MQ 类至少触发两次验证不重复生效。
- **权限**：有权限账号可操作；无权限账号菜单不可见且直调接口 403/失败。

## 层 A：后端功能测试（FUNC）

**REST 调用规范**：经网关或本地端口直调；请求头按项目认证要求携带（如 `Authorization: Bearer <token>` 及租户/客户端标识头，具体从登录接口响应或前端真实请求中抓取，禁止假设）；断言项目统一响应包装结构（Phase 0 确认，常见形态：data 包裹型如 `R<T>`、平铺分页型如 `TableDataInfo`）；分页接口断言总数与行数据一致。

**其他接口形态（按 Phase 0 确认的形态等价执行）**：GraphQL 直调 query/mutation，断言 `data` 与 `errors`；gRPC 用 `grpcurl` 或项目客户端 stub 直调；CLI 以真实进程调用，断言退出码/stdout·stderr/产物文件；SDK·库在示例工程中直调 API，断言返回值与副作用。

**DB 断言构造法（适用于任意模块）**：从交付标准的数据模型/表设计章节提取表清单，按以下五类模式为每张表生成断言 SQL（占位符按实际表名列名替换）；无直连 DB 的交付按 env-preflight §2 的替代通道（API 回读/可观测产物/只读控制台）执行同等断言：

```sql
-- ① 主档类：关键字段全列比对（状态机字段、金额、时间、外键）
SELECT <id_col>, <status_col>, <amount_cols>, <time_cols>, <fk_cols>
FROM <主表> WHERE <biz_key>='<值>';

-- ② 明细类：行数与逐行金额（行数=预期条数；Σ明细 == 主档总额）
SELECT COUNT(*) FROM <明细表> WHERE <fk>=<主档id>;
SELECT <line_cols> FROM <明细表> WHERE <fk>=<主档id>;

-- ③ 日志/流水类：事件存在性与字段完整（时间、操作人、快照、流水号）
SELECT <event_col>, <time_col>, <actor_col>, <snapshot_cols>
FROM <日志表> WHERE <biz_key>='<值>' ORDER BY id DESC;

-- ④ 配置/字典类：生效配置唯一、字段完整
SELECT <cols> FROM <配置表> WHERE <status_col>=1 AND <del_flag_col>=0;
SELECT <type_col>, <label_col>, <value_col> FROM <字典表> WHERE <type_col>='<类型>';

-- ⑤ 权限/菜单类：菜单条数、类型、权限标识、父级与排序
SELECT <id_col>, <name_col>, <parent_col>, <order_col>, <type_col>, <path_col>, <perms_col>
FROM <菜单表> WHERE <perms_col>='<perms>';
```

**典型 FUNC 检查点类型（按标准映射）**：新增/编辑/删除/详情 CRUD；必填与长度边界；数值上下限（临界值 0、max、max+1）；唯一性冲突；状态机合法/非法流转；终态后禁止再操作；越权访问他人数据；无效参数报文明晰。

## 层 B：集成测试（INTEG）

按交付标准的"依赖/关联"章节展开，常见模式：

- **网关链路**：小程序/App 端接口经网关 → 端侧 BFF/业务服务 →（RPC）→ 后端服务；断言链路返回与落库一致；端侧服务是否禁止直连业务库等链路红线以 Phase 0 确认为准。
- **异步通知**：触发业务事件 → 断言通知记录（类型/来源/接收人/文案）落库且接收人范围正确（含"收不到"的反向断言）；通知组件异常时主业务不阻断（可用错误参数诱导验证）。
- **定时任务**：按标准窗口/条件造数 → 触发 Job → 断言生效（DB 状态翻转 + 通知产生）→ 再触发验证幂等 → 清理造数。
- **MQ**：触发事件 → 经管理台/DB 断言消息产生与消费结果。
- **权限菜单**：登录后菜单树结构/顺序/文案符合标准；角色仅勾选菜单即可操作（无按钮级要求时验证无 F 节点）。
- **开通/联动**：审批通过后联动能力（账号开通、能力开关、状态回填）逐项断言。

## 层 C：端到端测试（E2E）

> E2E 是结束 loop 的硬门槛：含 UI 的检查点必须在真实渲染环境逐步走查（打开→点击→填写→提交→断言渲染+控制台无错）；过程件逐步落 `LOOP_TEST_DIR/<端>/<CP-ID>/`。API 直调只能作为 FUNC/INTEG 层手段，**禁止替代 UI 交互链**（手传参数会掩盖入口缺失/弹窗打不开/确认态不联动类缺陷）。

**交付形态 → E2E 配方路由**（形态在 Phase 0 确认，自动化通道在预检确定）：

| 交付形态 | E2E 手段 | 配方 |
|----------|----------|------|
| Web 管理端 / H5 / 静态站 | chrome-devtools MCP（playwright/browser-use 备选） | §C.1 |
| 小程序 | miniprogram-automator / 微信开发者工具自动化 | §C.2 |
| 原生 App / 桌面端 | 预检 §6A 确定的通道（既有测试工程/Appium/Maestro/OS 级自动化） | 断言类别照 §C.1/C.2 执行，坑清单参照 §C.2.1 #6 降级规则 |
| 纯后端 API / CLI / SDK·库 / 数据管道 | 真实入口场景链（无 UI 走查，但门槛同样硬性） | §C.4 |

### C.0 前端消费层三大断层（API 通过 ≠ 页面能用，逐 CP 必查）

| 断层 | 典型事故 | 必做断言 |
|------|---------|---------|
| **JSON 类型**：后端 BigDecimal/Long 序列化为字符串 | 前端 `x.toFixed()` 抛 TypeError → 整页渲染中断（连带所有后续交互失效）；`reduce 累加` 变字符串拼接（单笔正常、多笔爆炸） | 页面真实渲染出金额/列表；多笔数据场景下合计正确；控制台无 TypeError |
| **响应结构**：`R<T>`（data 包裹） vs `TableDataInfo`（total/rows 与 code 平级） | 前端取 `res.data.rows` 永远 undefined → 列表永远为空（API 直调看 total/rows 却是对的） | 页面渲染出行数与 DB 一致，而非只看接口响应 |
| **二进制/产物**：拦截器对 blob 直接返回 Blob 本体 | 页面取 `res.data` 得 undefined → 导出文件内容为字符串 "undefined"（请求参数断言全部通过） | **打开产物文件验证内容**（Excel 有行有列、图片可预览），不止断言请求发出 |

### C.1 管理端（chrome-devtools MCP 配方，playwright MCP / browser-use 等价替代）

工具序列：`list_pages` → `new_page`/`navigate_page` → `take_snapshot`（拿元素 uid）→ `click`/`fill` → 再 `take_snapshot` 断言 DOM → `take_screenshot` 存证 → `list_network_requests` 断言请求/响应 → `list_console_messages` 断言无报错。

通用断言类别（具体断言点从 plan.md 来）：
- **导航/布局**：菜单层级、面包屑、Tab 结构、Badge 计数与标准一致；
- **查询区**：标准要求的筛选字段齐全，搜索/重置生效（网络面板参数佐证）；
- **列表**：列与标准一致（含金额格式化、划线/标签/进度条等展示规则）；多值字段全量展示；
- **表单/抽屉/弹窗**：必填校验、边界拦截、提交 loading+disabled 防重、成功后 Toast+列表刷新；
- **组件状态变化**：弹层出现/消失、Toast 出现、Badge 变化、按钮态迁移，用前后两次 `take_snapshot` 对比断言；
- **原型对照**：原型为静态 HTML 时可用 `navigate_page` 直接打开，与实现页面同屏逐块比对（布局、字段、文案、交互状态）；原型的状态映射、计算公式、文案映射以其 script 为准（template 与 script 不一致时以 script + 交付标准文档为准）。

### C.2 小程序（miniprogram-automator 配方）

```js
const automator = require('miniprogram-automator')
const mp = await automator.launch({ cliPath: '<见 preflight>', projectPath: '<mp 编译产物目录>' })
const page = await mp.reLaunch('/<分包>/<页面>')   // 路径以 plan.md 为准
await page.waitFor(1000)
const el = await page.$('<selector>')              // 选择器以编译产物为准
console.log(await el.attribute('disabled'))        // 断言禁用/加载态
await el.tap()
const data = await page.data()                     // 断言页面 data（金额/状态/列表）
await mp.screenshot({ path: '<RUN_DIR>/evidence/<CP-ID>/shot.png' })
```

通用断言类别：
- **入口可见性与可达性**：按标准/账号角色断言入口显隐；**每个业务动作的完整点击链真实走一遍**（入口→弹窗可开→确认态联动→可提交→可返回），典型漏测：协议确认组件挂在页面上却没有任何打开入口、自定义导航页缺返回按钮；
- **表单流**：必填联动禁用、步骤条、选项多选/单选、合计联动计算；
- **弹窗流程**：多步确认弹窗的顺序、前置条件（如滚动到底/勾选后才可点）、按钮禁用迁移；
- **状态页/续办页**：按接口返回驱动渲染对应状态（用不同测试账号/造数覆盖各态）；
- **列表页**：筛选 Chip 换行无横向滚动（元素宽度+`page.data` 断言）、空态、加载更多；**渲染行数与接口/DB 对拍**（防响应结构错配致永远空列表）；
- **鉴权隔离**：未登录跳登录；他人数据不可见（账号 A/B 对照）。

### C.2.1 微信小程序实战坑清单（历史事故归档，逐项对照检查）

| # | 坑 | 症状 | 检查/修复要点 |
|---|-----|------|--------------|
| 1 | **主包引用分包模块** | 运行时 `module 'pages-sub/...' is not defined`，主包页面白屏（编译/直调接口均正常） | grep 主包（pages/、components/）import 是否指向分包路径；被主包依赖的 service/组件必须位于主包（分包引主包合法，反向非法） |
| 2 | **UnoCSS/原子类名冲突** | 自定义类名碰上原子类（如 `fixed`/`block`/`grid`）被注入 position:fixed 等 → 元素脱流浮动、布局错乱 | 自定义类名避开原子类保留字（用 is-xxx/业务前缀）；见到「滑动时某块固定不动/叠在中间」优先怀疑此坑 |
| 3 | **组件库 API 误用**（如 wot 的 datetime-picker 无 `:show` 弹出模式，是 cell 触发型；`display-format` 回调收列数组非时间戳） | 渲染层 `undefined is not iterable`、日期显示 NaN、组件自渲染成 cell 落到页尾、点击无反应 | 用法必须参照项目内已验证的同组件页面；修复后必须 UI 层重验（此类错误 API/DB 层永远测不出） |
| 4 | **TableDataInfo 结构错配** | 页面取 `res.data.rows` → 列表永远空；API 直调断言却通过 | 前端类型定义与页面取数对齐 total/rows 平级结构；E2E 断言渲染行数 |
| 5 | **BigDecimal 字符串** | `.toFixed()` 抛 TypeError 白屏；`reduce` 金额累加变字符串拼接（多笔才爆） | 所有金额消费点 `Number(x ?? 0)` 包裹；同类排查 grep `\.(amount|price|Amount|Price)\.toFixed` 与 reduce 累加；造数必含 ≥2 笔场景 |
| 6 | **自动化链路阶梯**：Node≥18 无法无 shell spawn .bat；新版工具 checkVersion 崩；screenshot/元素查询可能失效 | automator.launch 失败/连接挂起/截图超时 | 降级阶梯：外部 `cli auto --auto-port` + `automator.connect`（若 checkVersion 崩则 monkey-patch）→ 页面 data/路由断言 → H5 同源页用浏览器工具 → BLOCKED 交用户；每降一级记 ADR，结论上限 BLOCKED |
| 7 | **交互前置被 API 直调绕过** | 提交接口验证通过，但 UI 上根本无法完成前置（如协议弹窗无入口 → 永远无法提交） | 每个提交类动作必须有一条纯 UI 走查记录（不手传任何参数） |
| 8 | **造数清理副作用** | 删掉测试账号后，工具缓存的旧 token 对应 uid 已不存在 → 提交报「用户信息异常」 | 清理后主动告知用户：需清缓存重新登录；有 Redis 缓存的主数据修改须走页面不能直改 DB |

### C.2.2 UI 一致性走查清单（每个页面随 E2E 顺带执行；命中即按「UI 微调授权」修复）

- **文本完整性**：状态标签/按钮/列头无截断省略号（最长枚举值代入验证，如 4~7 字状态）；
- **无意外滚动**：常规分辨率下列表无横向滚动条；
- **规格统一**：同一页面族字号/行高/tag 尺寸一致；同类组件（抽屉/弹窗/表格/筛选）不出现第二种交互风格；
- **导航闭环**：自定义导航页有返回入口；流程页可退可进；
- **文案规范**：无「选填/预留/后续接入/敲定中」等非正式文案；必填项有红星标识；合理默认值（日期默认今天、金额默认应付余额等，仅空值填充）；
- **边界展示健壮**：空数据有空态；超长文本省略+悬停完整；哨兵值/极端日期不出现荒谬展示（如「剩余 26000 天」应显示为语义化文案）。

约束：修复仅限不改设计、不改内容、不引入新风格；布局结构/交互模式/配色体系变更只列建议交用户。

### C.3 E2E 旅程

从交付标准的端到端场景章节逐条编排：每条旅程跨端连续执行，**每个状态迁移点同时断言 DB + 异步通知 + 各端 UI**，形成完整证据链；旅程中各步骤的证据统一挂在该旅程 CP 目录下按步骤编号。

### C.4 无 UI 形态的 E2E（纯后端 API / CLI / SDK·库 / 数据管道）

E2E = 从**真实入口**按交付标准的业务场景章节编排完整场景链，与 FUNC 层单点直调的区别在于**连续性与状态传递**（上一步的真实产出作为下一步输入，禁止手工构造中间态跳步）：

- **纯后端 API**：按业务旅程编排真实调用序列（如 创建→审核→执行→查询→关闭），每步断言响应 + 数据层 + 异步副作用（通知/消息/任务）；鉴权与幂等场景纳入旅程（无权限调用、重复提交）；
- **CLI 工具**：以真实进程调用编排使用场景（含参数组合、管道/重定向、错误输入），断言退出码、stdout/stderr、产物文件内容（打开验证，不止断言存在）；交互式命令用 expect 类工具或降级为用户人工配合（记 ADR）；
- **SDK·库**：在独立示例工程中按 README/文档的使用路径完整消费（安装→初始化→核心 API 链→错误处理→资源释放），文档示例代码必须原样可运行——跑不通即 FAIL（文档也是交付物）；
- **数据管道/批处理**：以真实触发（调度/事件/手动等价命令）跑全链路，断言各阶段落数、最终产物、幂等（重跑不重复）与失败恢复路径；
- 过程件同样落 `LOOP_TEST_DIR/<端>/<CP-ID>/`（请求响应记录/终端会话日志/产物文件副本），判定证据归档 `evidence/`；"页面渲染断言"由**最终产物内容断言**等价替代（照 C.0 第三行：打开产物验证内容，不止断言生成动作成功）。

## 层 D：非功能测试（NFR，仅交付标准含可度量指标时）

> 原则：只验收交付标准**明示且可度量**的指标；标准没写的不自创（改进建议只写入报告）；缺专业手段的显式 BLOCKED，禁止用"感觉不慢/应该安全"替代数据。

- **性能/响应时间**：用轻量压测工具（如 `hey`/`ab`/`autocannon`，或 `RUN_DIR/scripts/` 并发脚本）按标准的并发/时长对指标接口施压，断言 P95/P99/错误率；需要分布式压测、长稳测试 → 超纲，标 BLOCKED 并建议专项压测；
- **容量/大数据量**：按标准量级造数（授权内，`[VERIFY]` 前缀，用后清理），断言该量级下分页/查询/导出可用且不超时；
- **安全冒烟**：权限/越权已在通用断言覆盖；追加输入类冒烟（SQL 注入/XSS 载荷经 UI 与 API 双入口提交，断言被拦截或转义、无泄露报错细节）；专业渗透/漏洞扫描 → 超纲，标 BLOCKED 建议专项安全测试；
- **容错/降级**：仅本地/独占环境且用户明确授权时，可停掉依赖组件（下游服务/MQ/缓存）断言标准要求的降级行为与恢复；**共享环境禁止故障注入**；
- 证据：压测输出/计时数据/量级断言结果存 `evidence/<CP-ID>/metrics.txt`；造数与清理 SQL 照预检 §7 规则成对留存。

## 证据格式（每个 CP 目录 `evidence/<CP-ID>/`）

| 文件 | 内容 | 必需性 |
|------|------|--------|
| `api.json` | 请求方法/路径/关键入参 + 响应报文 | 接口操作必有 |
| `db.txt` | 执行 SQL + 结果集（当轮新取） | 有 DB 预期时必有 |
| `shot-*.png` | 关键 UI 状态截图（操作前/后） | E2E 必有 |
| `network.txt` | 相关网络请求摘要（URL/状态/耗时） | UI 触发接口时必有 |
| `console.txt` | 浏览器/小程序控制台错误（应为空或解释） | E2E 必有 |
| `metrics.txt` | 压测/计时/量级断言数据 | NFR 类 CP 必有 |
| `verdict.txt` | PASS/FAIL/BLOCKED + 差异明细（预期 vs 实际） | 必有 |

## 修复参照与同类排查（修复前必做）

- **参照实现**：修复前先定位项目中同类既有实现作参照——后端参考同模块既有 Service/Controller 的分层与注解用法；管理端参考既有页面的组件选型、表单/抽屉/字典用法；小程序参考既有页面的组件库与样式约定（如 rpx、列表组件）。修复产物的命名、结构、风格必须与参照一致；禁止引入项目未使用的新组件库/新样式/新依赖。确无参照时在 fixes.md 说明理由。
- **同类排查**：根因确定后用 Grep 在白名单内扫描同模式缺陷，常见模式：集合只取首个元素展示（`list[0]`/`[0].name`）、提交接口缺防重拦截、枚举/状态文案硬编码、表单提交无 loading+disabled、金额未用 BigDecimal、时间计算未按标准规则。命中点连同"整类修复/逐点修复"决策记入 fixes.md 与 ADR；白名单外命中只写入报告。
- **UI 风格断言**：E2E 时同时断言组件用法与项目既有页面一致——同类型组件（抽屉/弹窗/表格/筛选）不应出现第二种交互或视觉风格。

## 修复后重验纪律

- 修复只改白名单文件；每个修复动作立即按模板登记 `fixes.md`；
- 先单点重验转 PASS（新证据），再下一轮全量回归；
- 任何"通过"结论前必须重新执行验证命令并读输出（verification-before-completion）。
