# 基线清单(baseline)

本文件是 env-bootstrap 的核心资产:六个通用域(D1-D6)+ 一个条件域(D7,仅 multi-repo)的最佳实践基线。Phase 1 扫描、Phase 2 挑选、Phase 4 验证均以本清单为唯一依据,不维护第二套验证清单。

每个检查项一张四字段表:如何探测、三态([缺失] / [已有·建议补齐] / [已覆盖])各自的判定条件、补齐动作与模板引用、生成时需要的输入。判定证据冲突时按确定程度排序取信:`CI/构建文件 > 代码事实 > 文档 > 口头描述 > 模板默认写法`;无法判断覆盖程度时一律标 `[已有·建议补齐]`,交 Phase 2 用户决定。

## 附录 A:P0 铁律示例库

供 Phase 2 收集铁律时兜底:用户说不出铁律时,按项目类型从下列示例中挑 2-3 条,替换成项目内真实的模块/表/接口名后与用户逐条确认。示例均为完整可改写句式,确认前不得直接写成「必须/禁止」级规则。

### 支付类项目

1. 禁止修改对账与清算核心逻辑(如 `reconciliation/` 模块),任何变更必须先出 ADR 并经资金安全负责人评审。
2. 不得改动扣款与退款主链路的接口契约与状态机流转,新增能力只能以旁路扩展方式接入。
3. 资金流水表只允许追加记录,禁止 UPDATE/DELETE 存量流水,冲正必须以红字新记录实现。

### SaaS 类项目

1. 多租户数据查询必须带租户隔离条件(如 `tenant_id`),禁止任何绕过租户过滤器的裸查询。
2. 禁止修改认证与授权中间件(登录、会话、权限校验链路),相关需求必须单独立项评审。
3. 公共 API 不做不兼容变更:字段只增不删不改义,废弃字段走版本化与灰度下线流程。

### 数据类项目

1. 禁止修改数据脱敏管道的脱敏规则与执行顺序,新增数据源必须先接入脱敏再入仓。
2. 不得改动调度依赖图(DAG)中已有任务的上下游关系,新任务只能挂接不能重排存量链路。
3. 禁止对生产数据表执行无 WHERE 条件的全表 UPDATE/DELETE,批量修数必须走审批过的修数脚本。

### AI 类项目

1. 禁止改动训练数据管道的清洗与采样逻辑,数据配比变更必须记录 ADR 并可回溯复现。
2. 提示词(prompt)必须走版本管理,禁止在代码中直接热改线上提示词内容。
3. 推理服务对外接口保持向后兼容:输入输出 schema 只增不删,模型切换不得改变响应结构。

## 附录 D:D8 抽样一致性检查规程(判 [已覆盖] 的前置条件)

目标:把 D8 从"查存在"升级为"查真实",防止地图初始化后随代码演进变成误导源(过期上下文比没有上下文更危险)。每项检查写成"命令 + 期望 + 三态映射",agent 执行、结果可复核。

**第 0 步·新鲜度筛(决定抽样强度)**:

- 地图时间:`git log -1 --format=%ct -- docs/maps/<map>.md`;源侧时间与期间提交数:`git log -1 --format=%ct -- <源路径>` 与 `git rev-list --count --since=<地图时间> -- <源路径>`;
- 源路径映射:code/domain-map → 构建文件与 src 一级目录;api-map → 路由/controller/网关配置目录;data-map → DDL/迁移/实体目录;env-map → 配置目录;
- 口径(建议值,可按项目调整):源侧晚于地图超 30 天 **或** 期间源侧提交 ≥ 10 → 该图标"疑似过期",必须执行下方完整抽样;否则每图抽 1 条即可。

**第 1 步·正向锚点抽样(每图抽 2-3 行,不足全查)**:

- code-map:所抽行"入口"列路径 `test -f/-d` 存在;"依赖方向"引用的模块名在本图模块列存在;
- domain-map:"涉及模块"列在 code-map 有登记(交叉引用);【待确认】占位存活超 90 天记失真;
- api-map:"契约位置"路径存在;"前缀"在路由/网关源路径 `grep -rl "<前缀>"` 至少命中 1 个文件;
- data-map:所抽表名与状态机字段名在 DDL/迁移/实体路径 grep 命中;
- env-map:"配置来源"路径存在;全图凭据正则(password=/token/AK/SK)必须零命中。

**第 2 步·反向抽漏(防"新东西没上图")**:

- code-map:构建文件模块声明/src 一级目录抽 2-3 个 → 必须在地图模块列出现;
- data-map:`git log --diff-filter=A --since=<地图时间> --name-only -- <迁移目录>` 取新增迁移的目标表 → 必须在地图出现;
- api-map:同法取地图时间后新增的 controller/route 文件 → 其前缀必须在地图出现。

**判定口径(三态映射)**:单图任一锚点失效或反向遗漏 → 该图 [已有·建议补齐],差距报告写明"哪一行、哪个锚点、命令与输出";源路径探测不到(如无迁移目录/非 git 仓库) → 该项记"无法机检"交 Phase 2 用户裁决,**不判失真**(防跨技术栈误报)。

演进方向:本规程的命令均为确定性检查,后续可脚本化为 map-check 类门禁(二期,需配置化源路径映射以避免跨栈误报)。
