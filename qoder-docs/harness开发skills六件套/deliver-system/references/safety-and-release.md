# Safety and release

## 何时读取

在涉及身份权限、敏感数据、第三方服务、依赖升级、迁移/删除、外部写入、付费资源、预发布/生产环境或最终 release-ready 判定前读取。

## 默认边界

默认交付目标是 `acceptance-ready` 或 `release-ready`，不是自动生产发布。Skill 不购买服务、不获取或记录生产凭据、不绕过权限、不替代法务/合规/安全负责人和最终业务验收人。

即使 Qoder、MCP、浏览器或项目脚本技术上能够执行生产、付费、凭据、真实数据或破坏性动作，也必须针对精确动作重新取得用户授权；工具可用性不构成授权。

## 风险识别步骤

1. 标记数据分类、信任边界、角色权限、外部服务和供应链变化。
2. 判断操作是否可逆、是否影响真实用户/数据、是否付费、是否扩大访问范围。
3. 对认证、授权、租户隔离、公共 API、迁移和生产基础设施提升风险等级。
4. 记录威胁、缓解、Owner、残余风险和需要的人工审批；架构决定写 ADR，产品风险接受写 PDR/验收记录。
5. 先在隔离/预发布环境验证；发布前确认备份、迁移、回滚、监控、告警和 Runbook。

## 最低安全门禁

- 输入验证、错误处理、最小权限和服务端授权检查。
- 正向与负向权限矩阵，防越权和租户间访问。
- 依赖与密钥扫描；适用时运行 SAST、契约和故障路径测试。
- 敏感数据不得进入日志、测试制品、报告或仓库。
- 安全相关行为具备必要审计日志，但不记录机密。
- 迁移在干净环境演练，并验证失败恢复或明确不可逆风险。
- 上线后具有健康检查、关键指标、日志、告警和可执行回滚步骤。

## 必须显式授权的操作

- 生产部署、生产配置或真实用户通信。
- 删除/覆盖真实数据、不可逆迁移或大范围重写历史。
- 创建付费资源、改变账单或启用有成本的外部服务。
- 使用、轮换或扩大生产凭据和访问权限。
- 接受高严重度安全、隐私、合规、可用性或数据完整性风险。
- 关闭保护、跳过 R3/R4 门禁或以已知失败发布。

授权必须说明精确目标、环境、影响、成本/风险、备份和回滚；授权一个动作不自动授权后续同类动作。

## 发布步骤

1. 确认 release commit、制品摘要、环境和 Gate 4/5 证据新鲜。
2. 对账范围、已知问题、延期项、风险接受、迁移、回滚和 Runbook。
3. 部署预发布，复验关键旅程、监控和故障恢复。
4. 生成 Acceptance Report、Release Notes 和部署/回滚清单。
5. 取得所需业务、安全和生产授权，再执行批准的发布通道。
6. 发布后执行 Smoke、观测和审计；失败时按预定阈值回滚并记录事件。

## 输入与输出

**输入：** Delivery Contract、威胁/风险、release commit、Gate Manifest、迁移/回滚方案、环境与授权。

**输出：** 安全检查结果、风险登记、审批记录、Release Notes、Runbook、验收报告和发布/回滚证据。

## 硬门禁

- 无精确授权不得执行上述高风险动作。
- 存在未处理的严重安全问题、旧证据、关键测试失败或无法回滚的未知风险时不得标记 release-ready。
- 不得把“技术测试通过”替代业务、安全或生产审批。
- 生产发布后 Smoke/观测失败达到阈值时必须停止扩大发布并回滚或请求用户。

## 停止条件

缺少权限、凭据、备份、回滚或审批；目标环境无法唯一识别；预发布与生产配置差异无法评估；严重漏洞或数据风险未解决；发布窗口/外部服务不可用；用户要求的操作超出 V1 能力边界。生成阻塞和风险报告，不尝试绕过。
