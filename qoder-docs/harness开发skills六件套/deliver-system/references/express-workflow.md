# Express workflow（体验优先轨）

## 何时读取

双轨路由选定 EXPRESS 后完整读取本文件。EXPRESS 的唯一优先目标：让用户尽快拿到"能点、能操作"的体验版本，再决定是否继续投入工程纵深。

## 适用与禁用

**适用**：新建或改造单一 Web 应用/功能；风险 ≤R2；用户明确想先看到运行效果；原型/想法尚不稳定需要快速试错。

**禁用（必须 FULL）**：支付、认证/权限、数据迁移、生产数据、多租户、不可逆操作、付费外部服务；用户明确要求完整保障流程。

## E1 意图速记（分钟级，不超过一页）

只写一个文件 `delivery-docs/intent/express-intent.md`：

```markdown
# Express Intent — <项目/功能名>
更新时间：<ISO 时间> | 状态：draft / confirmed

## 目标（1~2 句）
## 核心用户旅程（3~5 条，每条一行：角色 + 操作 + 期望结果）
J1: ...
J2: ...
## 明确不做（本轮不实现的内容）
## Mock 边界（哪些数据/接口用 mock，真实化留到 E5）
## 技术选型（一行：框架/UI 库/启动命令）
```

规则：

- 不建 OpenSpec Change、不写 requirements.json、不启用确定性 helper。
- 有原型图/参考稿时复制到 `delivery-docs/intent/`，逐旅程标注对应页面。
- 旅程数超过 5 条或出现 R3+ 要素时，停下建议切换 FULL 轨。
- 阻塞性歧义（如核心旅程含义不明）立即问用户；其余按合理默认值继续并在文件中记录假设。

## E2 骨架搭建

目标只有一个：**跑起来**。

1. 用 CLI 脚手架初始化（如 `vite`/`next` 等现代框架），不从零手写工程配置。
2. 只实现核心旅程涉及的页面、路由与组件；非旅程页面用占位。
3. 数据一律 mock/内存实现，集中放在一个 mock 层（如 `src/mocks/`），便于 E5 替换；mock 数据要贴近真实业务形态（名称、金额、状态用业务化示例）。
4. 不写自动化测试、不做性能优化、不追求完整错误处理——但核心旅程上的交互反馈（loading/空态/成功提示）要有，否则用户无法体验。
5. 骨架能启动后立刻进入 E3，不在 E2 停留打磨。

## E3 可操作体验版 + UI 闭环走查

1. 启动 dev server（后台运行），调用 RunPreview 把预览交给用户。
2. 同时按 [ui-loop-verification.md](ui-loop-verification.md) 执行闭环走查：
   - 走查清单直接来自 express-intent.md 的旅程列表（J1..Jn）；
   - 每条旅程真实浏览器逐步操作并断言；
   - 缺陷即修，只重验受影响旅程 + 核心冒烟；
   - 全部通过或达 3 轮上限才结束本阶段。
3. 证据落 `delivery-docs/verification/loop-<时间戳>/`。
4. 走查未全通过时不得进入 E4 请用户体验（用户不应替 Agent 找已知缺陷）。

## E4 用户体验确认门（EXPRESS 唯一强制人工门）

1. 明确告知用户：预览地址、可体验的旅程清单、已知限制（mock 边界、不做项）。
2. 收集反馈并归类：缺陷（回 E3 修复重验）/ 新需求（追加到 express-intent.md，标注是否本轮做）/ 体验调整（回 E3）。
3. 反馈收敛后，将结论写入 `delivery-docs/intent/feedback.md`：用户确认可接受的体验版状态 + 余留事项清单。
4. 用户确认前不得宣称体验版完成。

## E5 升级补齐（可选，切换 FULL 轨）

用户决定继续投入时升级到 FULL 轨，按序补齐：

1. 把 express-intent.md + feedback.md 提炼为正式需求与验收（`delivery-docs/product/`），必要时用 spec-writing 类流程。
2. 建 OpenSpec Change（垂直切片），替换 mock 为真实数据层/接口。
3. 补自动化测试（按 testing-and-acceptance.md 的风险分级）。
4. 重跑 UI 闭环走查（真实数据路径）+ 目标回归。
5. 文档、报告按 FULL 轨完成标准收口。

升级不是重来：已确认的页面结构、交互与走查清单全部继承。

## 停止条件

进入 `WAITING_USER` 并报告：出现 R3+ 要素需要切换 FULL；核心旅程含义无法确定；脚手架/环境持续失败超过修复上限；用户反馈与已确认意图冲突。
